# Scene Report System

> Spatial report layer (`server/scene_report/`), decoupled from the autonomous mission loop. Turns the reconstruction into structured, evidence-grounded facts and an LLM-authored report, surfaced on the summary page — **live as the scan grows** (progressive, Phase 3) and **finalized when the scan stops** (Phases 1–2). Finished scans are then **persisted per-user** (Phase 4) and can be **revisited + queried face-to-face afterward without a GPU** (Phase 5).
>
> Triggered from [server/app.py](streaming-server.md); persistence resources live on Modal (see [modal-deployment.md](modal-deployment.md)). The phased plan is in `scene_report_plan.md` (root).

## Key files
- `features.py` — `SceneFeatureExtractor.extract(solver, detections, scene_center)` → `SceneFacts`: room AABB dimensions, camera-trajectory length, deduped object inventory with **world-frame** locations, pairwise distance relations, coarse coverage. Duck-typed (no GPU imports).
- `report.py` — `SceneReportBuilder.build_final(solver, facts, scene_center)` → `SceneReport` via an injected `OpenRouterClient`; falls back to a fact-only (degraded) report if there is no client or the call fails. `build_incremental(...)` is the progressive variant: folds the latest facts + a small, newest-biased keyframe set into the *previous* report (`progressive=True`, `final=False`); falls back to a fact-refreshed previous report so the live report never regresses.
- `keyframes.py` — `choose_frame_refs` (bounded, deduped selection: optional `prefer_submap_ids` first — used by the progressive report to front-load the newest submap — then object evidence, then one representative per submap) + `encode_frames` (lazy `ObjectDetector` base64, best-effort).
- `schemas.py` — Pydantic `SceneFacts`, `ObjectInstance`, `SpatialRelation`, `SceneMetrics`, `SceneReport` (every claim carries `EvidenceRef`s), plus `ObjectDescription`/`ProductMatch` for fine-grained object identification (an optional `ObjectInstance.description`).
- `object_enricher.py` — `ObjectEnricher` turns a coarse detection ("laptop") into a rich `ObjectDescription` ("MacBook Pro 14″, Space Black, likely M3"): a VLM captions a crop of the object's best keyframe, **optionally grounded by a reverse image search** (`SerpApiLensProvider` → Google Lens) so brand/model cite real listings. GPU-free / duck-typed (numpy + pydantic + lazy `requests`); includes the pure-numpy `crop_from_box`. See **Object enrichment** below.
- `store.py` — `InMemoryScenePersistence` (duck-typed default) + `ModalScenePersistence` (Phase 4): durable per-`user_id`+`scan_id` store, **modal-free** (injected KV `store` handle + `blob_root` + `commit`/`reload` callables, so it unit-tests with a `dict`+`tmp_path` and ships in the existing `add_local_dir`). Metadata (report/facts JSON + keyframe manifest) in the KV store; keyframe JPEGs + the **full-fidelity point-cloud artifact** (`cloud.npz` — `np.savez_compressed` of the complete **world-frame** cloud, N×3 float32 positions + N×3 uint8 colors, **no stride/cap**) on the Volume. `save_scene`/`list_scenes`/`get_scene`/`get_keyframe`/`get_cloud`/`delete_scene`; `get_cloud` returns world-frame arrays and transparently reconstructs the world frame for legacy recentered `points.bin` scans. Retention is **unlimited by default** (`max_scans_per_user=0`) so every scan keeps its artifact (a positive cap re-enables oldest-first eviction).
- `cloud_io.py` — dependency-light (numpy-only) helpers shared by the broker's scene routes: `downsample_cloud` (display subsample) + `build_ply_bytes` (binary little-endian PLY, **no Open3D**, so it runs on the CPU broker).

## Final-report flow
`stop_slam` → `handle_stop` awaits `finalize_detection_state`, then dispatches `_build_and_emit_scene_report` on `_agent_executor`. The report is cached in `_last_scene_report` and **broadcast to all of the worker's sids** — the summary page is a *separate socket* from the scanning viewer, so a per-sid emit would never reach it. A late-opening summary page fetches the cached report via `get_scene_report`. `/reset` clears the cache via `_clear_scene_report()`.

## Progressive-report flow (Phase 3)
`stream_results` calls `_maybe_dispatch_progressive_report(result)` after each SLAM update. Throttled (one build per `SCENE_REPORT_PROGRESSIVE_EVERY_N_SUBMAPS` **and** at most every `SCENE_REPORT_PROGRESSIVE_MIN_INTERVAL_S`), with an in-flight guard so an LLM call can't overlap the next tick. The build runs on `_agent_executor` (off the event loop), reads only the reconstruction (so it works with the agent **disabled** / reconstruction-only), and **broadcasts `scene_report_update`** to all sids. `_build_and_emit_scene_report` sets `_scene_report_finalized` *before* building, and the progressive build decides+emits under `_progressive_report_lock`, so the final `scene_report_ready` can never be clobbered by a late progressive update. `get_scene_report` hands a late-joining summary page the running progressive report when no final exists yet. All progressive state is cleared by `_clear_scene_report()`.

The **demo flow has no `stop_slam`** (the server-side `VideoFeeder` is driven by `/api/demo/start`/`/api/demo/stop`), so the report is also triggered when a demo video **finishes naturally** (`VideoFeeder.on_complete`) or on `POST /api/demo/stop`, both via the debounced, thread-safe `_trigger_scene_report_threadsafe` → `_run_end_of_scan_report` (waits for the frame queue to drain, then finalizes + builds). The same `on_complete` is wired for the local `python -m server.app --video` path.

## Persistence flow (Phase 4)
A `scan_id` (uuid hex) is minted at every scan start via `_begin_new_scan()` (which also `_clear_scene_report()`s) — the three start sites are `handle_frame` auto-start, `/api/demo/start`, and the local `--video` feeder; `/reset` nulls it. After the final report is built, `_build_and_emit_scene_report` calls `_persist_scene_report` **before** broadcasting `scene_report_ready` (flipped 2026-08-13: the native app holds its "Saving" state until that event and then immediately lists the library, so emit-first raced the durable save and a fresh scan could be missing from the first library fetch; the summary page waits a few extra seconds of blob writes, absorbed by the app's 120 s save deadline): it re-runs `choose_frame_refs`+`encode_frames` for the cited keyframes and `StreamingSLAM.gather_world_point_cloud()` for the **complete world-frame cloud** (every submap, **no stride/voxel/cap** — the durable artifact; display downsampling happens later on read), then `_scene_persistence.save_scene(user_id=_worker_expected_user_id, scan_id, …)`. Best-effort — a persistence failure never breaks the report (the event still fires). A scan can also finalize+persist with **no client at all** via the abandoned-scan salvage (see [streaming-server.md](streaming-server.md)). `_scene_persistence` is injected by `configure_scene_persistence(...)` (mirrors `configure_session_store`); `None` in plain local runs.

## Revisit + Q&A flow (Phase 5), GPU-free on the broker
The broker `web()` and the GPU worker both mount `asgi_application`, so the same Flask routes serve everywhere — but the dashboard hits the **always-on CPU broker** so reading history never boots an A100. Routes (all under `/api/`, auto-authed by `require_modal_auth`, hard-scoped to `claims["sub"]`): `GET /api/scenes` (list), `GET /api/scenes/<id>` (report+facts+manifest), `GET …/keyframes/<key>` (JPEG bytes), `GET …/points` (the broker recenters the stored world-frame cloud and **downsamples to `SCENE_DISPLAY_MAX_POINTS`** on read, returning a **`SLAMUpdate`-shaped** JSON so the revisit page calls `SceneManager.updateVisualization()` unchanged), `GET …/cloud.ply` (streams the **full** cloud as a binary PLY for download/export, openable in CloudCompare/MeshLab — auth via `?auth_token=`), `DELETE /api/scenes/<id>`, and `POST /api/scenes/<id>/qa`. The QA route grounds an `OpenRouterClient` (`_get_assistant_client()`, reads `OPENROUTER_API_KEY`) in the persisted facts + report + question-relevant keyframes, and **validates the LLM's `focus` target against the stored inventory** (an invented object name → `focus=None`). `_relevant_scene_objects` ranks objects by a **weighted, stem/substring-aware overlap** of the question against each object's **name** (strongest) and its **relation + report context** (the partner names/qualifiers from `relations` and any report summary/observation text that mentions the object) — so non-exact phrasings ("what's on the board" → *whiteboard*, "are there plants" → *potted plant*, "near the TV" → the TV's neighbours) still re-rank, not just exact name words (helpers: `_stem`/`_terms`/`_substr_match`/`_relation_terms_by_object`/`_report_terms_by_object`). Ties — notably the common **no-lexical-match** case — break by **question↔object embedding similarity** when `SCENE_QA_EMBED_TIEBREAK` is on (`_embedding_similarities` makes one batched `OpenRouterClient.embed` call reusing `OPENROUTER_API_KEY` — OpenRouter serves an OpenAI-compatible `/embeddings` endpoint — and cosine-ranks; **degrades to static confidence** when disabled, keyless, or on any failure), else by confidence. The cited **evidence keyframes track the answer, not a static top-3**: the core builds a bounded, labeled candidate menu from the relevant objects' evidence (`_candidate_keyframes`, capped at `SCENE_QA_CANDIDATE_IMAGES`, each noting what it `shows`), attaches those images, and the model **cites its own** supporting frames — `_select_evidence` keeps the cited `(submap_id, frame_idx)` refs we actually resolved bytes for (in the model's order, capped at `SCENE_QA_MAX_IMAGES`), falling back to the candidate order only when the model cites nothing valid. (Previously the images were the blind confidence-ranked first 3 and the model's `evidence` was discarded, so every question surfaced the same pictures.) This grounding is a **single shared core — `_grounded_scene_answer(facts, report, question, history, image_loader)`** — used by **both** chat surfaces so they can't drift: `_answer_scene_question` (revisit) feeds it the persisted record + a manifest/blob `image_loader`, while the **live summary-page chat `POST /api/assistant/chat`** (`assistant_chat`) feeds it the worker's cached `_last_scene_report` (final, or the in-scan progressive, via `_current_scene_report_dict()`) with no keyframes. Both return the canonical `{answer, model, degraded, focus, evidence}`. The core grounds in the object inventory (world-frame centers/extents), pairwise `relations`, and room type + up-to-scale `dimensions` — the summary chat previously shipped only object **names** + scan counts, hence its "I don't have spatial context" answers. Frontend: broker-served `revisit.html`/`src/revisit.ts` (new Vite entry) mirrors the summary page's layout — the report as a full-width hero (shared `src/sceneReportView.ts`, refactored out of `summary.ts`) on top, with the point cloud (+ a **Download .ply** link to the full artifact) and a camera-flying Q&A box (`SceneManager.focusOnPoint`) in a two-column row below; the landing `app/components/SceneHistory.tsx` lists scans (full-width card grid) from the broker and links to `…/revisit.html#scan_id=<id>&token=<jwt>`. On load `revisit.ts` exchanges that short-lived hash JWT for a **durable broker session token** (`POST /api/session/refresh`) and uses it for every later call, so the human-paced Q&A no longer 401s when the hash JWT expires mid-visit (the static-hash-token trap — see [gotchas.md](gotchas.md)); a 401/403 now surfaces an honest "session expired — reopen from dashboard" instead of masquerading as "I could not find that in the scan." `<img>`/points blob requests authenticate via the `?auth_token=` query param (accepted by `_extract_http_token`).

## Object enrichment (fine-grained identification)
Detections are open-vocabulary, so a detection's label **is its CLIP query** ("laptop") — CLIP/SAM3 retrieve+segment, they don't *generate* text. `ObjectEnricher` adds the missing captioning step so the product surfaces "MacBook Pro 14″, Space Black, likely M3" / "Air Jordan 1, Off-White".

- **Crop → VLM:** `StreamingSLAM.make_detection_crop` reads the keyframe tensor + the cached SAM `box_2d` (highest CLIP×SAM) and tight-crops the object (GPU executor). `enrich_from_crop` then runs the VLM **off the GPU loop** (agent executor) via `OpenRouterClient.chat_json_model(ObjectDescription, …, images_b64=[crop])` with an evidence-first prompt (read visible text/logos → identify → calibrate confidence, hedge low as "likely…"). Results are **cached per `(submap, frame, query)`** on `StreamingSLAM._description_cache`, so a click, a re-click, and the finalize pass share one call. Cache is purged with the SAM cache on query removal / reset.
- **On click ("click-in"):** the existing detection-card click (`describe_detection` socket event in `server/app.py`, sibling of `get_detection_preview`) returns a `detection_description` with the `ObjectDescription`; the viewer renders it in the preview modal (`UIManager.renderDescription`, frontend types in `webserver/src/types.ts`).
- **Top-N at finalize:** `_build_and_emit_scene_report` calls `StreamingSLAM.enrich_top_n(detections, OBJECT_ENRICH_FINALIZE_TOP_N)` right before `extract`, so the most-confident objects carry a `description` into `SceneFacts` → the persisted record → revisit (the report view surfaces it via `sceneReportView.ts`, matching report-object names to fact-object queries). The progressive in-scan build is left unenriched (keeps mid-scan ticks cheap).
- **Reverse image search (Phase B, OFF by default):** SerpApi's Google Lens takes a **public image URL** (no raw upload), so when `OBJECT_ENRICH_REVERSE_SEARCH` is on the worker stashes the crop bytes under an unguessable token and serves it briefly at `GET /api/crop/<token>.jpg` (no Clerk auth — the token is the capability; TTL `OBJECT_ENRICH_CROP_TTL_S`) on its public tunnel (`WORKER_PUBLIC_URL`, set from the `modal.forward` URL). `_make_crop_url` mints it; matches returned by SerpApi are **server-authoritative** (the model can't invent listings). Needs `serpapi-secret` — only referenced by `modal_streaming.py` when the operator opts in at deploy time, so plain deploys never require it. Crops of private spaces go to a third party → gate behind consent before enabling.

## Gotchas
- Detection `bounding_box` centers are stored recentered around `latest_scene_center` (see `StreamingSLAM._compute_bboxes_for_keys`); the extractor re-anchors them to the world frame by adding `scene_center`. Geometry is read via `Submap.get_points_in_world_frame(graph)` / `get_all_poses_world(graph)`, **not** the display frame that `_build_full_payload` recenters every extraction.
- The map is up-to-scale (not metric, see `scale_solver.py`) and the world frame is not gravity-aligned — the report hedges sizes as approximate and does not assert a vertical axis / floor-to-ceiling height (`SceneMetrics.vertical_axis_known` is always `False` in v1).
- Frontend: both `scene_report_ready` and `scene_report_update` carry the `SceneReport` shape (typed in `webserver/src/types.ts`, with `progressive`/`final` flags), are wired in `SLAMConnection.ts` (`onSceneReport` / `onSceneReportUpdate`), and render into the `#sceneReportBody` panel by `summary.ts` — the progressive variant shows a pulsing "Live" badge (`report-banner-live`).
- Persisted point cloud (Phase 4) is the **full, un-recentered world-frame cloud** (`cloud.npz`) — the durable artifact; the record's `scene_center` holds its mean. **Display is derived on read** by the broker: recenter (− `scene_center`, matching the live viewer) then downsample to `SCENE_DISPLAY_MAX_POINTS`; the full cloud is downloadable as PLY (`…/cloud.ply`). Object centers in `SceneFacts` are world-frame, so the revisit Q&A focus subtracts `scene_center` before `focusOnPoint`. `gather_world_point_cloud` reads the graph-aware `get_points_in_world_frame(graph)` (not `Submap.get_voxel_points_in_world_frame`, whose `self.poses[0]` path can be stale) across **all** submaps (matching the live viewer + `Map.write_points_to_file`), with **no stride/voxel/cap** — earlier a fixed `voxel_size` (the map is up-to-scale, so the grid was blind to the scene's units) plus a low point cap collapsed the cloud into a sparse "skeleton"; downsampling now lives only on the display read path, never in the stored artifact.

- Frontend nav: the summary page's **Back** button routes to the Vercel landing **dashboard** (not the in-worker `/viewer.html`, which renders empty once the scan ends), derived from the access token's `azp` origin via `getDashboardUrl()`. See [frontend.md](frontend.md).

## Config env vars
- `SCENE_REPORT_MODEL` — report LLM (defaults to `SPATIAL_ORCH_MODEL`, else `google/gemini-3-flash-preview`).
- `SCENE_REPORT_FALLBACKS` — CSV fallback models (default `openai/gpt-4o-mini`).
- `SCENE_REPORT_TIMEOUT_S` (default 30), `SCENE_REPORT_RETRIES` (default 1), `SCENE_REPORT_MAX_KEYFRAMES` (default 12).
- Progressive (Phase 3): `SCENE_REPORT_PROGRESSIVE` (on by default), `SCENE_REPORT_PROGRESSIVE_EVERY_N_SUBMAPS` (default 2), `SCENE_REPORT_PROGRESSIVE_MIN_INTERVAL_S` (default 12), `SCENE_REPORT_PROGRESSIVE_KEYFRAMES` (default 4).
- Persistence (Phase 4): the full cloud is stored **uncapped** (the artifact). `SCENE_DISPLAY_MAX_POINTS` (default 1000000) only bounds the **display** downsample the broker does on read (0 = no downsample); it never touches the stored artifact or the PLY download. Retention is unlimited by default (`ModalScenePersistence(max_scans_per_user=0)`). Q&A (Phase 5): `SCENE_QA_MAX_OBJECTS` (default 8), `SCENE_QA_MAX_IMAGES` (default 3, cap on **shown** cited keyframes), `SCENE_QA_CANDIDATE_IMAGES` (default 6, the labeled keyframe menu the model cites evidence from — must exceed `SCENE_QA_MAX_IMAGES` to give a real choice). Semantic tie-break: `SCENE_QA_EMBED_TIEBREAK` (**off by default**; any of `1/true/yes/on` enables it — adds one batched embeddings call per QA, degrades to confidence on failure), `SCENE_QA_EMBED_MODEL` (default `openai/text-embedding-3-small`, via OpenRouter), `SCENE_QA_EMBED_MAX_OBJECTS` (default 50 — skip embeddings for scenes with more objects to bound cost).

- Object enrichment: `OBJECT_ENRICH_ENABLED` (on by default), `OBJECT_ENRICH_MODEL` (default `google/gemini-3-flash-preview`), `OBJECT_ENRICH_FALLBACKS` (CSV, default `openai/gpt-4o-mini`), `OBJECT_ENRICH_TIMEOUT_S` (default 20), `OBJECT_ENRICH_FINALIZE_TOP_N` (default 8). Reverse search (Phase B, **off by default**): `OBJECT_ENRICH_REVERSE_SEARCH` (`1/true/yes/on`), `SERPAPI_API_KEY` (via `serpapi-secret`), `OBJECT_ENRICH_CROP_TTL_S` (default 600), `WORKER_PUBLIC_URL` (auto-set by `modal_streaming.py` from the tunnel URL).
