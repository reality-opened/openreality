# Known Gotchas

> Cross-cutting traps that aren't obvious from the code. Skim this before editing the SLAM core, the Modal deploy spec, or the auth path.
> Subsystem-specific gotchas live in their own docs ([scene-report.md](scene-report.md), [modal-deployment.md](modal-deployment.md) → per-user broker/worker).

- `get_projection_matrix` in `graph.py` has a typo (`return projection_matri`) — **the method is broken**, avoid calling it.
- `normalize_to_sl4()` calls are commented out in `PoseGraph`; GTSAM matrices may not be strictly SL(4).
- LC submaps (`is_lc_submap=True`) are excluded from pose output and visualization; iterate `non_lc_submap_ids` for display.
- Detection cache in `StreamingSLAM` is keyed by `(submap_id, frame_idx, query)` and guarded by `_detection_lock`.
- All viewer calls in `StreamingSLAM` must be guarded by `if self.viewer is None: return`.
- Modal `download_models` does NOT pre-cache PE-Core CLIP or SAM3 weights — those are pulled lazily on first detection request. First detection after a cold start has extra latency.
- `modal_streaming.py` stubs out `decord` (no Python 3.11 wheel) before installing SAM3. Don't import video-path utilities from SAM3 — they will silently no-op.
- **`modal_streaming.py` adds `server/` source file-by-file** (`add_local_file`/`add_local_dir` for `app.py`, `agent/`, `llm/`, `scene_report/`, …), not the whole `server/` tree. A **new `server/` subpackage must be added to that list explicitly**, or the deploy crashes at import with `ModuleNotFoundError` even though `app.py` (which imports it) ships fine. Likewise, **`server/webserver/*.html` entry points are added one-by-one** (only `src/` is a whole dir) — a new Vite entry's `.html` must be added there too, or the in-image `vite build` silently omits that page.
- **A `modal deploy` does NOT take effect for new sessions until the broker container cycles.** The broker `web()` is `min_containers=1`/`max_containers=1` with `timeout=86400`, so the pre-deploy container survives the deploy — and it spawns GPU workers through the `session_worker.spawn` handle it hydrated at *its own* startup, i.e. the **old code version**, for up to 24 h. After every deploy: `modal container list`, then `modal container stop <broker ta-id>` (Modal restarts it on the new version immediately; note this drops any live broker connections). Symptom that bit us: a fixed bug reproducing identically post-deploy from a worker started *after* the deploy.
- Clerk JWT verification (`server/app.py`) fails hard at import time if `CLERK_JWKS_URL`, `CLERK_JWT_ISSUER`, or `CLERK_JWT_AZP` are unset — local runs must export these even when not testing auth flows. (JWKS keys are now TTL-cached with refetch-on-unknown-`kid` so a Clerk key rotation no longer bricks a warm container — see `fixes.md` #3.)
- **`DANGEROUSLY_DISABLE_AUTH=1` disables ALL auth** (both `_verify_http_token` and `_verify_socket_auth` early-return synthetic `tier=approved` claims) — the whole deployment becomes open to anyone with the URL, with unlimited scans. It exists only for throwaway test apps (e.g. validating the VGGT-Omega backbone against the Modal URL directly, no Clerk/landing). It's OFF unless the **deploying shell** exports it (`_SESSION_RUNTIME_ENV` defaults it to `"0"`) and prints a loud boot banner. **Never set it on the production `web` app.** See [modal-deployment.md](modal-deployment.md) → *Throwaway test deployments* and [access-control.md](access-control.md).
- **The bundled SPA carries one static Clerk JWT in the URL hash (`#token=…`) and can never refresh it** — the landing app mints it via the `modal-slam` JWT template; viewer→summary just re-propagate it (`buildAuthHash`). The live socket only verifies the token **once** in `handle_connect` (the 10-min `SESSION_TIMEOUT_SEC` is a plain timer, not a re-auth), so the viewer keeps streaming after the token expires — but any **new** connection or HTTP call (e.g. opening `/summary.html` after a scan, or its chat) re-verifies the now-expired token and fails with `invalid_token`. Keep the `modal-slam` template's **Token Lifetime ≥ `WORKER_MAX_LIFETIME_SEC`** (default 3600s) so a token outlives a full session; the `slam_session` cookie auto-inherits that lifetime (`/auth/session` sets `expires=exp`). The GPU-free, fresh-token path for finished scans is the dashboard → `revisit.html` flow ([scene-report.md](scene-report.md)).
  - **HTTP / revisit is now fixed durably:** `_verify_http_token` accepts a broker-minted **session token** (HS256, `_verify_any_token` dispatches on the JWT `alg`) alongside the Clerk JWT; the revisit page mints one on load via `POST /api/session/refresh` (`SESSION_TOKEN_TTL_SEC`, default 12h, signed with `SESSION_TOKEN_SECRET` — per-process fallback resets on redeploy, fine for the single-instance broker), so its reads + Q&A outlive the hash JWT. **Still on the static token (by design):** the **live Socket.IO path** (`_verify_socket_auth`) + the summary-page live chat — kept Clerk-only to keep zero risk on the scanning path, so the Token-Lifetime band-aid above still governs *those*. Extending `_verify_any_token` to the socket would close that too.
- Demo videos in `server/demo_videos/` are Git LFS pointers. Run `git lfs pull` before `modal run modal_streaming.py` or only LFS pointer files will be uploaded.
- The Vite dev server's mock middleware (`apiMockPlugin`) intercepts `/api/*` and `/reset` — if you need to test against the real backend from `vite dev`, run `npm run build` and serve via `node server.js` instead.
